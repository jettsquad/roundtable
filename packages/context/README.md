# @squad/context — `ctx.teamContext`

上下文装配。四个插件里的 ②。

## 拥有

- **窗口筛选**：从团队日志切出这一轮携带哪些事件（`window.ts`）
- **时间线渲染**：把事件翻成席位读到的文本（`timeline.ts`）
- 引用合并：主持人点名的旧发言并入窗口并标记
- 检查点边界：按 `coversUpTo` 切、跳过被作废的那份
- 折叠阈值的评估与触发（消费 `@squad/shared` 的 `team-checkpoint-threshold`）

## 绝不拥有

| 不拥有 | 归谁 |
|---|---|
| 检查点**正文的生成** | ③ `ctx.secretary`（这里只决定它是否进窗口、放在哪） |
| 谁发言、什么顺序 | ① `ctx.teams` |
| 判据的召回与投放规则 | ④ `ctx.reasoning` |
| 团队日志的写入 | ① `ctx.teams`（这里只读） |

## 装配是两层，不是一层

```
selectContextEvents   哪些事件 travel   ← window.ts
      ↓
renderTimeline        它们怎么读         ← timeline.ts
```

1.x 的两层**互相不知道对方的事件清单**，第二层以 `if (kind !== "discussionTurnEnd") return []`
收尾——任何它没被教过的类型静默丢弃。检查点就死在这里：第一层正确地按检查点截断了历史，
第二层把检查点本身扔了。**历史没了，替代品也没送到，全程无报错。**

所以渲染层**不许有 catch-all**。每个类型必须落进三张表里的恰好一张：

| 表 | 含义 |
|---|---|
| 渲染 | 讨论本身，以及替代被折叠部分的检查点 |
| 故意不渲染 | 合法出现在主持人日志上、但席位不该读的簿记 |
| **禁止** | 只有跑过回合才会留下的类型——它们的出现意味着**主持人说话了** |

第三张表是 1.x 没有的。主持人节点是锚点不是决策者；它一旦跑回合，就是让 LLM 当主持人。
把 `turn/start`、`assistant/message` 这些归进「故意不渲染」，会让装配层成为**唯一看见
了违约却一声不吭的组件**——和 1.x 那个静默丢弃是同一种病，只是换了一层。所以它们抛错。

一个测试守着这三张表：dsh 的 `KNOWN_SESSION_EVENT_TYPES` 里每个类型都必须**恰好**
落进一张。harness 长出新事件类型时，失败点在这个点名它的测试里，而不是在某个席位
悄悄看不见东西。这是 `.dsh-link.json` 那道守卫的另一半。

## 为什么这些纯函数在这里而不在 `@squad/shared`

按 `@squad/shared` 的「只出不进」：新逻辑放消费它的插件，出现**第二个**消费者才提升。
窗口筛选与时间线渲染只有这一个消费者——它们就是这个插件的领域本身。
