# Squad 2.0

Squad 1.x（`/Volumes/Jett/projects/Squad`，tag `v1.0`）已功能冻结，只修 bug。
新能力全部在这里做。

## 2.0 为什么要重做架构

两件事，1.x 的形态承载不了：

1. **个人思维系统（Lil X）** — 让系统先学会使用者解决问题的**逻辑**，再学会他的**判断标准**，
   并随实践迭代。它要求应用提供一个「插槽」：这套东西按使用者不同而不同
   （Allen 用是 Lil Allen，Jason 用是 Lil Jason），且必须能带走。
   设计见 `docs/specs/2026-08-18-personal-reasoning-system.md`。

2. **插件化** — 借鉴 DSH（`~/.local/share/roundtable/deepseek-harness`，Cordis 插件框架）。
   1.x 的主进程有 12,568 行，其中绝大部分是装配与 IPC —— 那正是要被重构的对象，
   而不是要被继承的资产。

## 从 1.x 继承什么

| 类别 | 内容 | 处理 |
|---|---|---|
| 原样搬 | `domain-core`、`orchestrator-core`、检查点/装配那批纯函数、**以及它们的全部测试** | 连测试一起，测试是验收标准 |
| 搬知识不搬壳 | 三个 executor（Claude Code / Codex / DSH）里的踩坑知识 | 按 2.0 的插件接口重写外壳 |
| 不搬 | `electron-entry.ts`、`electron.ts`、`preload`、`renderer` | 它们是旧架构的形态本身 |

## 阶段与门控

- **阶段 0 · 定边界**（当前）— 不写产品代码。读 DSH 插件机制 → 定插件边界与契约 → 写 2.0 架构文档。
  **门控**：能否用一页纸说清「一个插件是什么、能拿到什么、绝不能碰什么」。
- **阶段 1 · 立骨架** — 插件宿主 + 一个 executor 插件，跑通「1 人团队发一条消息收一条回复」。
  **门控**：最小闭环跑通。**这是全项目的生死线**——它验证插件契约成不成立。
- **阶段 2 · 搬能力** — 一次一个插件，每个都带着它的测试。
  **门控**：任何时候都能跑，不允许出现「三个月不能运行」的状态。
- **阶段 3 · Lil X** — 先写路径（捕获/提炼/存放），后读路径（定位/投放）。
- **阶段 4 · 切换** — 一次性数据迁移工具，然后 1.x 退役。

## 两条硬约束

- **独立的 appId / userData。** 1.x 开发态用的是 Electron 默认目录，2.0 必须换掉，
  否则调试 2.0 会写坏 1.x 正在用的团队数据。
- **本仓库没有远端，是有意的。** `docs/` 里有使用者的方法论，属于个人资产。
  将来若要加远端，先逐份审查 `docs/`。
